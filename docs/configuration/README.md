# Configuration

Wasel is configured by four kinds of input. Knowing which one you are touching tells you when the change takes effect and what else to update.

| Kind | Where | When it is read |
|---|---|---|
| Environment variables | process environment and `.env` | at process start |
| Tunable YAML | `config/*.yaml` | mostly at start; `monitor.yaml` on every request, `eval.yaml` on every evaluation run |
| Reference data | `data/*.yaml`, `data/templates/`, `data/seed/` | at start (and by the generator) |
| Code constants | `src/wasel/**` | at import; changing one means a code change and a test run |

The settings that decide *what the process is allowed to do* (mode, sending, webhook, caps) are environment variables. The settings that decide *what a score is* are in YAML and code.

## Every configuration file

| File | Controls | Affects | Safe to change? | After changing |
|---|---|---|---|---|
| `.env`, environment | mode, sending, webhook, caps, LLM providers, paths | runtime | yes; secrets stay out of git | restart. Export provider variables if you do not start with `make up` or `make serve`. |
| `config/scoring.yaml` | scoring rules, thresholds, lexicons, timings, ROI assumptions | runtime scoring, outbound, evaluation, training impact | yes, carefully; every value is an assumption | restart, `make eval`, `make test` |
| `config/llm.yaml` | which prompt, schema, limits and default models each LLM role uses | runtime, evaluation | yes; use the documented procedures | restart, `make eval` |
| `config/prompts/*`, `VERSIONS` | model instructions, sha-locked | extraction and drafting quality | only through a version bump | restart, `make warm`, `make eval` |
| `config/schemas/*.json` | model output shapes | runtime, mirrored by Pydantic | rarely; change code and tests with it | restart, `make test` |
| `config/monitor.yaml` | monitor window, minimum samples, drift and ceiling values | `/api/monitor`, alerts | yes | none (read per request) |
| `config/eval.yaml` | evaluation floors | the gate | raise freely; lower only with review | `make eval` |
| `config/probe.json` (absent) | Gemini schema style | Gemini fallback | optional | restart |
| `data/catalog.yaml` | products, aliases, prices, generator weights | scoring (matching, price), generator, seed | yes | restart; regenerate and retrain if the change should be reflected in the model; re-`make warm`; catalog is mirrored to the database on boot |
| `data/zones.yaml` | places and their zone, zone keywords | scoring, rules extractor, generator | yes | restart; regenerate and retrain |
| `data/phrase_banks.yaml` | authored customer phrases by label and language | rules extractor, generator, evaluation | yes, with native-speaker review | `make generate`, `make golden`, `make eval`; not part of `config_hash` |
| `data/templates/outbound.yaml` | outbound message templates | drafts, prefilter, guard-classifier training | yes, with native-speaker review | restart, `make test`, `make eval`; not part of `config_hash` |
| `data/draft_guard.yaml` | guard-classifier training bank | draft classifier, golden outbound set | yes | `make golden`, `make eval` |
| `data/seed/demo_seed.json` | the eleven sample conversations | boot seeding, "Try this order", smoke test | yes | `make warm` (new text needs cache entries), `make mocks` |
| `data/seed/extraction_cache.jsonl` | recorded extractions for the samples | offline runs | generated by `make warm` | do not edit by hand |
| `data/monitor_reference.json` | drift baseline | monitor | generated | `python -m wasel.monitor --build-reference` |
| `models/risk_xgb_v1.json` | the risk model | scoring | generated by `make train` | restart |
| `pyproject.toml` | ruff and pytest configuration, package metadata | development | yes | `make lint`, `make test` |
| `requirements*.txt` | pinned dependencies | everything | pins are exact; update deliberately | `make setup`; retrain if XGBoost changes minor version |
| `Makefile` | commands and their defaults | development, operations | yes | [commands](../development/commands.md) |
| `web/.env.example`, `web/next.config.mjs` | web UI API origin, static-export settings | web UI | rarely | `make web` |
| `dashboard/.streamlit/config.toml` | Streamlit theme and server options | dashboard | yes | restart `make ui` |
| `deploy/wasel.service` | systemd unit | deployment | edit `User` and `WorkingDirectory` on the host | `systemctl daemon-reload` |
| `.github/workflows/ci.yml` | CI jobs | CI | yes | push |

## What needs regeneration, retraining or redeployment

| If you change | You must also |
|---|---|
| The six features, their order or encodings (`ml/features.py`) | regenerate the dataset, retrain (`make generate`, `make train`), update the model card, rebuild golden sets and the monitor reference |
| `PRIOR` constants or generator distributions | same |
| Catalog or zones | restart; regenerate and retrain if the model should learn the new prices or zones |
| The extraction prompt, few-shot examples or schema | new prompt version, `PROMPT_VERSION`, `make warm`, live evaluation |
| A phrase bank | `make generate` (text columns change), `make golden`, monitor reference rebuild, `make eval` |
| The seed conversations | `make warm`, `make mocks`, check `tests/golden/hero.json` |
| Anything read at start | restart the process (`systemctl restart wasel`, or stop and re-run `make serve`) |

## Safety-relevant settings

Some values protect the system. Loosening one is a security change and should be reviewed as such:

- `APP_MODE` and everything that keys off it ([modes](../architecture/overview.md#modes)).
- `WA_SEND_ENABLED`, `WA_AUTO_SEND`, `WEBHOOK_ENABLED`, and the length requirements on `WA_APP_SECRET`, `WA_VERIFY_TOKEN` and `ADMIN_TOKEN`.
- `auto_send.*`, `outbound.judge.*` and the `prefilter` and injection lexicons in `scoring.yaml`.
- The evaluation floors in `eval.yaml`.
- `LIVE_LLM_DAILY_CAP` and the per-visitor caps.
- `HOST`: the default `127.0.0.1` keeps the app reachable only from the machine (or a reverse proxy on it).
